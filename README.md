# DSH Game Hub

DSH Game Hub 是一个本机运行的五子棋网页项目，目标是让 AI 伴侣在关键回合亲自参与，同时把普通走子交给零模型调用的本地算法。项目目前处于五子棋 Phase One，游戏服务只绑定 `127.0.0.1`，对局和游戏专属用量保存在本地 SQLite 数据库。

## 项目背景

这个项目从一个问题开始：如果另一套独立模型替 AI 伴侣下棋，能否算作“她在玩”？项目选择以混合模式回答：普通回合由本地算法托管；评分器认定为关键的局面，才将一个精简请求交给 DSH 主会话，由她查看自己的棋局并提交落子。此方案接受主会话排队和额外上下文成本，换取对局决策与既有会话身份、记忆和交流方式相连。

游戏服务只发送棋局 ID 与类型，桥接在本机绑定座位凭据。DSH 通过 `game_view` 获取自己的合法视图，再用 `game_play` 落子。方案 B（独立会话）通道保留但默认关闭；本地算法仍可作为普通回合和失败时的托管路径。此仓库不包含 DSH、QQ 桥接程序或任何 API 密钥。

## 设计记录节选

以下是项目设计笔记中的核心想法整理：

- **先决定谁在玩，再决定怎样接入。**同一个模型名称不代表共享同一段对话和记忆；如果项目的目标是让既有 AI 伴侣参与，关键回合应由她所在的会话做出选择。
- **算法托管与亲自决策是不同的参与方式。**本地算法适合处理普通回合和补位；关键回合交由 DSH 决策，避免把“系统自动下棋”描述成伴侣亲自选择。
- **少量真实决策比每步调用更可控。**只在评分器判断为关键局面时请求模型，并用真实用量记录校准成本，不把估算当成实际账单。
- **记录能延续信息，不能代替亲历。**棋谱和摘要有助于回顾，但无法完全还原当时的选择过程；项目保留逐手记录和每局总结的设计方向。

这些内容是对 `docs/DECISION_NOTES.md` 的整理摘录，技术行为以代码和 `docs/DECISION_MODE_PLAN.md` 为准。

## 环境要求

- Windows 10/11（提供 `.bat` 启动器；其他平台可运行 Node 命令）
- Node.js 24 或更高版本
- pnpm 11 或更高版本
- 若要让关键回合由 DSH 决策：另行运行 DSH 与 QQ 桥接，并启用桥接端的 `game_view` / `game_play` 工具

## 安装与启动

### 1. 安装 Node.js 和 pnpm

安装 Node.js 24+ 后，在 PowerShell 检查：

```powershell
node --version
corepack enable
corepack prepare pnpm@11.25.0 --activate
pnpm --version
```

确保 Node 主版本不低于 24，pnpm 主版本不低于 11。

### 2. 下载项目并安装依赖

在 PowerShell 进入解压后的项目目录：

```powershell
cd <项目目录>
pnpm install
```

`<项目目录>` 指你自己选择的克隆或解压位置。

### 3. 创建本机配置

复制模板：

```powershell
Copy-Item .env.example .env
```

本地网页默认使用 `http://127.0.0.1:8787`。如果要接 DSH 桥接，在 `.env` 中设置 `GAME_BRIDGE_URL` 和 `GAME_BRIDGE_SECRET`：URL 指向桥接本机提供的 `/internal/game/turn` 回调；密钥须与桥接配置完全一致。密钥只保存在本机 `.env` 和桥接本机配置里，不要提交或发到聊天中。可以用 Node 生成随机值：

```powershell
node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"
```

把生成值填入两端对应的配置。游戏服务只监听本机回环地址；不要将桥接回调暴露到公网。

### 4. 配置并启动 DSH 桥接（可选）

若希望关键局面由 DSH 主会话下棋：

1. 先按 DSH 与 QQ 桥接各自的安装说明启动它们。
2. 在桥接配置中选择 `companionDecision.mode: "dsh-session"`，并确认桥接回调地址、共享密钥与游戏 `.env` 一致。
3. 确认桥接已注册 `game_view` 和 `game_play` 工具。备用 `dsh-subagent` 模式默认关闭；`local` 可作为本地托管模式。
4. 游戏服务不需要启动独立模型 Worker，也不要求配置模型厂商 API Key。QQ 桥接是单独软件，不包含在本仓库内。

如果只想运行本地游戏，可跳过这一步；根据房间模式和桥接配置，普通走子仍由本地算法处理。

### 5. 启动游戏

Windows 用户可双击项目目录中的 `一键运行游戏.bat`。也可以在项目目录运行：

```powershell
pnpm start
```

浏览器访问 <http://127.0.0.1:8787>。停止服务时回到运行服务的终端按 `Ctrl+C`。对局数据写入本地 `data/games.sqlite`，刷新页面后可使用浏览器保存的座位凭据继续当前对局。

## 游戏专属 Token 用量

游戏页显示此项目累计用量和当前局用量。桥接只有在能够将 DSH 用量事件关联到棋局 ID 时才记录该局用量；普通 QQ 聊天用量不计入游戏统计。用量面板和命令行查询只读本地 SQLite 记录，不发起模型请求，也不额外消耗模型 Token。若服务未提供用量事件，项目不会估算缺失值。

可选命令行查询：

```powershell
pnpm usage
pnpm usage -- --game <gameId>
```

## 数据与安全边界

- `.env`、SQLite 对局数据、日志和依赖目录均为本地文件，不属于源码发布内容。
- `GAME_BRIDGE_SECRET`、座位凭据和 Worker 凭据不得提交到版本库。
- 游戏服务只绑定 `127.0.0.1`；不要直接改为监听公网地址。
- DSH/QQ 桥接和模型提供方由使用者自行安装、配置并承担相关费用。

## 项目结构

- `src/`：游戏服务、持久化、五子棋与用量查询
- `web/`：本地网页界面
- `phase0/`：模拟玩家接口
- `tests/`：规则与本地服务集成测试
- `docs/`：决策方案、设计笔记和验收资料
- `PROJECT_PLAN.md`：项目阶段计划与约束
