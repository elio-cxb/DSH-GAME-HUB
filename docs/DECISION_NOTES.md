# 设计决策摘录

本文将项目讨论中的设计判断整理为可公开分享的摘要，隐去私人对话细节。完整实现条件见 [`DECISION_MODE_PLAN.md`](DECISION_MODE_PLAN.md)，分期安排见 [`../PROJECT_PLAN.md`](../PROJECT_PLAN.md)。

## 谁在参与

项目最初可以让独立模型根据结构化棋局选择动作，工程上简单，但与既有 AI 伴侣的聊天上下文、记忆和人格没有关联。最终选择关键局面由 DSH 主会话决策：不是因为它吞吐更高，而是因为“谁在玩”是项目本身要回答的问题。

## 混合模式与成本

普通回合交给零模型调用的本地算法；评分器认定为关键的局面，才让 DSH 选择。每局调用预算保留上限，由评分器和真实用量记录共同约束，而不是为了固定次数耗尽预算。用量估算不能替代实际数据，缓存也不能当作成本保证。

## 记录与体验

棋谱和摘要能够同步发生过什么，却不能完全复制当时的选择过程。逐手记录用于短期回顾，每局总结用于长期检索；记录的作用是帮助对话接续，而不是冒充亲历。

## 给实现者的提醒

1. 先确认由谁决策，再设计调用链路。
2. 清楚区分本地算法托管与模型决策。
3. 关键回合才调用模型，并记录真实用量。
4. 为超时或桥接故障保留可控的本地降级路径。
